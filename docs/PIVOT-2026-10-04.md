# The pivot of 2026-10-04: virtual items, 0.x versions, a fresh repository

**Read this first in any new session.** It records why NeoFences changed direction, what was decided, what was
parked, and exactly what comes next. Decision: ADR-040 (`docs/DECISIONS.md`).

## Why

Hand-testing drag-in from Explorer (checklist K4/K5) showed that the original model — fences *are* the Desktop folder
(Stardock Fences' model: each Desktop file in exactly one fence, Takeover hides Windows' icons) — makes organizing a file
operation: dropping a file from another drive **copies** it onto the Desktop, and a Desktop file dropped from Explorer
hit a Windows "source and destination are the same" dialog (bug K5). The user wants NeoFences to be an **organizer, like
Rainmeter**, never a file manager: *"the actual item remains safe and sound from harm or mishaps"*; *"the desktop or any
other folder remains messy and unorganized in terms of this software."*

## The new model (decided by the user)

- **Every item in a fence is a virtual item**: a NeoFences record pointing at a target (file, folder, `.lnk` shortcut,
  symlink, app, website, Windows special item such as the Recycle Bin), with **its own name, icon and path**, all
  editable in an item **Properties** dialog. The same target may appear in several fences.
- **Nothing NeoFences does touches a real file.** Dropping anything onto a fence creates an item (never a copy or move);
  dragging between fences moves the item, **Ctrl+drag duplicates it**; dragging out to an app gives a **copy** of the
  file; Rename / icon / path change only the item; **Delete = remove the item**. Windows' full item menu (with real
  delete/rename) only behind Shift+right-click, clearly labelled.
- **Targets that change:** NeoFences watches the folders holding targets. Renamed in place → the item follows. Deleted or
  moved away → item shown **"missing"** with **Locate…** / **Remove**. On a drive that is not plugged in →
  **"unavailable"**, back by itself. **Limits:** at most ~64 watched folders; refresh batched (≤ 1 per fence per 2 s);
  beyond the limit, targets are re-checked when a fence shows and every few minutes. **Each fence menu has "Refresh".**
- **Native desktop icons are visible by default.** No Takeover. Settings offers **"Hide desktop icons while NeoFences
  runs"** (off by default; Windows' own setting; restored on exit, crash and Task Manager kill — the watchdog stays for
  this).
- **Kept:** fences, tabs, roll-up, lock, Peek, snapshots, game mode, Appearance (one title font, colours, wallpaper
  accent), auto-update, the Game Library (its items are NeoFences' own generated shortcuts — safe).

## Parked (in the git history bundle and the docs; come back as "dynamic fences" later)

- **Portals** (a fence that mirrors a folder's files live) and **Rules auto-sort** (filing new Desktop items) → later as
  *dynamic collections* (folder views that are read-only, "auto-collect" rules). The user does not need them now.
- **Takeover**, Inbox auto-fill and Desktop membership, item file actions (in-place rename, Recycle, drop-into-folder).
- **The search palette** (branch `m15-search-palette`, never merged) — in the local history bundle only.

## Hard rules (updated by ADR-040)

1. **NeoFences never modifies, moves, renames or deletes any user file** (organizing is item-only; removing a fence or
   an item never touches files).
2. **Native desktop icons always come back** when the user chose to hide them — clean exit, crash, Task Manager kill
   (watchdog), Explorer restart.
3–7 unchanged.

## Versions and repository reset

- The pre-pivot builds v1.0.0–v1.8.0 were **development builds**; they ran only on the developer's PC. Their history is
  kept in a local bundle (below), not on GitHub. Older docs (ADRs, SESSION-LOG, research) still say "v1.x": read those as
  pre-reset dev builds.
- **Versioning restarts at 0.x:** the reset codebase is **0.8.0**; the virtual-items release is **0.9.0**; **1.0.0** is
  the first version shared with friends.
- **GitHub** (`github.com/CipherSnowden/neo-fences`, public, not open source): reset to one fresh commit; the v1.8.0
  release, the 15 tags and the parked branch deleted. Commits use the GitHub noreply address; the private hub link lives
  only in the git-ignored `CLAUDE.local.md` (memory: never commit the personal address or the hub link).
- **Local backups in `F:\projects\`:** `neo_fences-backup.git` (mirror before the history scrub — never push it) and
  `neo_fences-history-2026-10-04.bundle` (the full scrubbed history up to the reset, all branches and tags).
- Config **schema numbers keep counting** (currently 4); they protect data from older builds and do not reset.
- The installed v1.8.0 and its data were removed from this PC (data backed up to
  `F:\projects\neofences-data-backup-2026-10-04\`). NeoFences is not installed until 0.9.0.

   (`docs/superpowers/specs/<date>-virtual-items-design.md`), plan, execute, review, release. Open questions for the

   "Hide desktop icons" option wording.
2. Remove the parked code paths in M18 (Takeover, membership, rules, portals, item file actions) — deletion over
   addition; keep the watchdog for the hide-icons option.
3. Later: M19 customization polish (Locate, Ctrl-duplicates, bulk refresh); M20 dynamic collections (folder views,
   auto-collect rules); code signing; the search palette if wanted.
