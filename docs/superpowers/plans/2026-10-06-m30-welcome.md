# M30 — First-run welcome (0.18.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fresh install's first fence welcomes the friend (Sort my desktop…, Add item…, Guide) until it gets an item; a sort that makes fences removes the still-empty welcome fence; the first start says where the tray icon is.

**Architecture:** Core gets `Fence.Welcome` (written only when true), `CreateDefault` sets it, and `WelcomeEdits` decides when the welcome ends (pure, test-first). The App shows a welcome panel in `FenceWindow` while the flag is set and the fence is empty, ends it in `ItemsChanged` (every add path goes through it) and after Add from desktop, and shows one tray notice on a `Fresh` start.

**Tech Stack:** .NET 10, C#, WPF, xUnit; PowerShell + UI Automation for the live check (scratchpad scripts).

**Spec:** `docs/superpowers/specs/2026-10-06-welcome-design.md` (approved 2026-10-06). Decision: ADR-051 (added by Task 3).

## How this plan is written

The code was built in a scratch worktree (`m30-proto`) and replay-verified on a fresh worktree of `main` at `2ca5aa3`:
the tests patch alone fails to build (13 errors: `Welcome`, `WelcomeEdits` missing — the RED), the Core patch makes
655 tests pass, the App patch builds with 0 warnings and 655 pass, and the tree is identical to the prototype. So Tasks 1
and 2 are **patches to apply** (write each exactly as shown with the Write tool; `git apply --whitespace=nowarn <file>`;
if one does not apply, stop). The docs are prose: Task 3 gives the outline and acceptance checks.

## Global Constraints

- Hard rules stand: no file is touched (sorting makes links; removing the welcome fence removes an empty fence only).
- No new dependency; no config schema bump (`"welcome": true` is additive and written only when true).
- UI copy, exactly: heading **"Welcome to NeoFences"**; line **"Fences hold links to your apps, games, files and websites — your files never move."**;
  buttons **"Sort my desktop…"**, **"Add item…"**, **"Guide"**; line **"or drop files, folders or links here"**; notice
  title **"NeoFences is running"**, text **"Its icon is in the notification area — on Windows 11 maybe behind the ^ arrow. Click it for the menu and Help."**
- The welcome appears only on a `Fresh` config load; an updating copy never sees it. The tray notice never shows in game mode.
- Hide-icons: the Add from desktop dialog's existing checkbox (spec §4 ruling); no second question.
- CLAUDE.md: menu/gesture changes update `docs/GUIDE.md` and the README quick start in the same commit as their docs task.
- Commits: single line, Conventional Commits, past tense, **no Co-Authored-By trailer**; secret scan (`gmail|claude\.ai/artifact`) before each commit.
- Version stays `0.17.0` until the release step; the release is 0.18.0.

## Review Focus

1. **Drops on the welcome**: a file dropped on the welcome panel's text or buttons lands in the fence (drops are taken at
   the window, not the list) and the welcome ends — checklist AP4.
2. **The welcome fence as a tab**: dragged onto another fence's title, then Sort my desktop… — the box stays whole and the
   welcome tab goes (Core test `AfterDesktopFill_RemovesAWelcomeFenceThatIsATab_AndTheBoxStaysWhole`; live AP7).
3. **Small or light**: the fence resized to its minimum, and Windows in light mode — the welcome scrolls and stays legible
   (theme resources only) — AP3.
4. **An existing user on a fallback**: config.json lost or unreadable with no usable backup loads `Fresh` and shows the
   welcome even though items.json holds old lists — acceptable (a fresh start), never removes an old fence (only flagged
   fences) — Core test `AfterDesktopFill_NeverRemovesAnOrdinaryEmptyFence`.
5. **Cancel and empty sorts**: Sort my desktop… cancelled, or a desktop with nothing to add — the welcome stays (Core test
   `AfterDesktopFill_KeepsTheWelcome_WhenTheSortMadeNoFilledFence`; live AP5).

+using NeoFences.Core.Items;
+
+namespace NeoFences.Core.Model;
+
+/// <summary>
+/// When the first-run welcome ends (M30, ADR-051). Pure: each returns the same config when nothing changes, so the host
+/// saves only on a change; none touches a file (hard rule 1).
+/// </summary>
+public static class WelcomeEdits
+{
+    /// <summary>A welcome fence that holds items is an ordinary fence from now on.</summary>
+    public static NeoFencesConfig ClearIfFilled(NeoFencesConfig config, ItemsDocument items)
+    {
+        if (!config.Fences.Any(fence => fence.Welcome && items.Of(fence.Id).Count > 0)) return config;
+        return config with { Fences = [.. config.Fences.Select(fence => fence.Welcome && items.Of(fence.Id).Count > 0 ? fence with { Welcome = false } : fence)] };
+    }
+
+    /// <summary>
+    /// Add from desktop put items into new fences: a welcome fence still empty was only the welcome, and goes (spec §3).
+    /// Nothing added, or only into existing fences: it stays.
+    /// </summary>
+    public static NeoFencesConfig AfterDesktopFill(NeoFencesConfig config, ItemsDocument items, int added, int newFences)
+    {
+        if (added == 0 || newFences == 0) return config;
+        foreach (var welcome in config.Fences.Where(fence => fence.Welcome && items.Of(fence.Id).Count == 0).ToList())
+            config = FenceEdits.DeleteFence(config, welcome.Id);
+        return config;
+    }
+}
