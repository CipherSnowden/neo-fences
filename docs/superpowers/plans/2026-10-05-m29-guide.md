# M29 — A guide for friends (0.17.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A newcomer can install NeoFences, sort their desktop in five minutes and find any feature with a picture: a rewritten README, `docs/GUIDE.md` with screenshots from a demo setup, and Help in the tray and Settings opening the guide.

**Architecture:** Docs in the repo (README.md, docs/GUIDE.md, docs/guide/*.png); the app gets two entries that open the guide's GitHub page through the existing open path. No Core change.

**Tech Stack:** Markdown on GitHub; .NET 10 WPF (two menu entries); PowerShell + UI Automation for the demo screenshots (scratchpad scripts, as in earlier live checks).

**Spec:** `docs/superpowers/specs/2026-10-05-guide-design.md` (approved 2026-10-05). Decision: ADR-050 (added by Task 5).

## How this plan is written

The app change was built in a scratch worktree (`m29-proto`) and replay-verified on a fresh worktree of `main` at
`7f47a45`: it applies, the solution builds with 0 warnings, 643 tests pass, and the tree is identical — so Task 1 is **a
patch to apply** (write it exactly as shown with the Write tool; `git apply --whitespace=nowarn <file>`; if it does not
apply, stop). The docs are prose: each docs task gives the outline and the acceptance checks; the text is written at
execution and the final review checks it against the app.

## Global Constraints

- Hard rules stand; the only app change is two entries opening `https://github.com/CipherSnowden/neo-fences/blob/main/docs/GUIDE.md`
  through `OpenItem` (off the UI thread, failures logged). No new dependency.
- UI copy, exactly: tray **"Help"** (above "Settings…"); Settings → About and logs **"Help (online guide)"**.
- Every menu entry, button, setting and key the docs name must exist with exactly that text in the app (checked against
  the XAML and the code, not memory).
- Screenshots: PNG in `docs/guide/`, each under ~400 KB, from the demo setup only; nothing personal in any shot (the
  user's name, email, private file names, the private hub link) — every shot is opened and checked before it is committed.
- The public repo never gets the personal email or the private hub link (secret scan before each commit).
- Commits: single line, Conventional Commits, past tense, **no Co-Authored-By trailer**.
- Version stays `0.16.1` until the release step; the release is 0.17.0.

## Review Focus

1. **Accuracy**: a step in the guide that names a menu entry, a gesture, a key or a setting that does not exist (or works
   differently) — a newcomer following it gets stuck.
2. **Safety words**: anything that suggests NeoFences moves, deletes or organizes files (it never does), or that hides
   icons for good.
3. **Install path**: SmartScreen and Smart App Control described as they appear on Windows 11 today; per-user install;
   updates and turning them off.
4. **Privacy**: any personal name, file or link in the README, the guide or a screenshot.
5. **Links**: relative links and anchors that break on GitHub (case, spaces, the `docs/guide/` paths).
